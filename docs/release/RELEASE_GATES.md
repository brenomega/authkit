# AuthKit v0.1 release gates

[Português (Brasil)](RELEASE_GATES-ptBR.md) | English is normative.

This is a live evidence ledger for the unpublished `0.1.0-rc.1` candidate. `VERIFIED LOCAL` is not a release approval. `NOT PROVEN` means exactly that: no result is inferred from unit tests, mocks, historical runs, configuration review, or an unavailable credential. No gate is not-applicable to the golden path.

| # | Mandatory gate | Current state | Current evidence | Exact remaining action |
| --- | --- | --- | --- | --- |
| 1 | Clean build and complete suite with real PostgreSQL/Redis | VERIFIED LOCAL | Final evidence `./mvnw clean verify` completed in 3m11s: 289 tests, zero failures/errors/skips; PostgreSQL 17.9 and Redis 7 Testcontainers passed; JAR and CycloneDX SBOMs produced. | Preserve the final evidence log and rerun only if application/test inputs change. |
| 2 | Fresh golden-path install using public production docs | VERIFIED LOCAL / INDEPENDENT OPERATOR PENDING | Fresh named volumes applied V1→V25; AuthKit/PostgreSQL 17.9/Redis 7.4/Caddy/Mailpit STARTTLS became healthy; TLS discovery, one-shot bootstrap/replay rejection, registration/confirmation/login/profile/refresh/replay/logout/introspection and rate/duplicate negatives passed. | Repeat on a clean host by an independent operator using only public docs (Gate 15); replace local CA/Mailpit with valid public TLS and real provider credentials in their gates. |
| 3 | TLS/proxy in same-site and cross-site topologies | NOT PROVEN | Local proxy configuration and edge tests are not topology proof. | Use valid DNS/certificates in both declared browser topologies; record browser/curl traces, origin/cookie/CORS behavior, and direct-backend denial. |

Until all gates pass with evidence bound to the same commit/tree and immutable image digest, the candidate is `NO-GO`. Only the maintainer can authorize publication, promotion, tagging, or risk acceptance.
