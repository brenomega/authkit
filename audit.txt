Executive Summary
Overall verdict: Not approved for production. AuthKit has a promising Spring Boot structure and some good primitives, but it is not production-ready under hostile traffic. The biggest blockers are incomplete auth lifecycle, insecure/unfinished refresh/logout/email-verification flows, no MFA/passkeys, weak authorization model, broken test verification, dangerous worker-token authentication, secret-like deployment values, vulnerable dependencies, and several security-sensitive race/logging/concurrency bugs.
Scores: production readiness 3/10, security 3/10, performance 4/10, maintainability 6/10, reference-authentication-model 2/10. Global architectural score: 3/10. Recommendation: No-Go.

Critical Blocking Issues
Refresh/logout lifecycle is incomplete. Login sets a Refresh-Token cookie in AuthController.java (line 58), and Redis stores refresh tokens in RedisTokenStorage.java (line 29), but there is no refresh-token endpoint, no rotation, no cookie clearing logout, and no current-session logout route.
Password reset has a race and token leakage risk. validateRecoveryToken and revokeRecoveryToken are separate operations in PasswordRecoveryService.java (line 104), allowing concurrent reuse. Reset links include token and email in a URL in PasswordRecoveryService.java (line 80), increasing leakage through browser history, referers, and logs.
JWT validation is incomplete. Tokens are issued with issuer authkit but no audience in AuthService.java (line 124), and the decoder in JwtConfig.java (line 53) does not configure explicit issuer/audience validators or key rotation.
Worker shared-secret auth is overpowered. WorkerAuthFilter.java (line 44) lets any request with X-Worker-Token become authenticated, and route rules only require .authenticated() for most non-public routes in SecurityConfig.java (line 96). This is a confused-deputy/privilege-boundary risk.
Sensitive values can leak to logs. LoggingAspect.java (line 127) masks by parameter name only. LoginRequest request and RegisterRequest request can stringify passwords when debug logging is enabled; newPassword is not masked.
Argon2 concurrency guard is broken. tryAcquire() failures still call release() in AuthService.java (line 99) and ProfileService.java (line 145), inflating permits under load.
Tests cannot currently validate production safety. Test execution fails due Mockito self-attach, and CI uses Java 17 while pom.xml declares Java 21: pom.xml (line 30), ci.yml (line 42).
Committed secret-like deployment values exist. docker-compose.yml (line 17) contains DB/Rabbit credentials; 05-secrets.example.yaml (line 12) contains DB/Rabbit/worker-token values. If reused, this is critical.
High-Risk Issues
Email verification is generated but not implemented or enforced. email_confirmed exists in User.java (line 94), but SecurityUser.isEnabled() always returns true in SecurityUser.java (line 112).
Registration leaks account existence with Email already in use in RegistrationService.java (line 44).
Login timing/enumeration leak exists because nonexistent users avoid Argon2 verification in AuthService.java (line 93).
Account lockout only records failed attempts for existing users and returns fake successful tokens when locked in AuthService.java (line 87).
Tenant isolation is nominal only. tenant_id is unique per user in V2 migration (line 12), and the Hibernate tenant filter in User.java (line 39) is never enabled.
Origin/IP trust can be bypassed from trusted internal ranges. K8s trusts 10.0.0.0/8 and 192.168.0.0/16 in 01-configmap.yaml (line 7), while CloudflareIpStrategy.java (line 42) trusts the CF-Connecting-IP header when present.
Current dependencies include known advisories: Spring Boot 3.5.13 affected by CVE-2026-40977; pgjdbc 42.7.10 affected by CVE-2026-42198.
Layer Findings
Authentication Architecture: 4/10, not production-ready. Strengths: clean controllers, 15-minute JWT access token, Redis-backed refresh-token storage, account lockout intent. Weaknesses: no refresh/logout/email verification/OAuth, fake locked login success, reset race. Missing protections: refresh rotation, logout-all/current logout, email confirmation gate, OAuth/OIDC, idempotent signup. Remediate by implementing explicit /refresh, /logout, /email/verify, OAuth if required, atomic reset-token consume, and real lockout responses.
Authorization and Access Control: 3/10, not production-ready. Strengths: /users/me avoids user-id path parameters; method security is enabled. Critical: worker shared secret can authenticate broadly. High: roles exist but are unused; no @PreAuthorize; tenant isolation unused. Remediate with deny-by-default route policies, scoped worker endpoints, mTLS or signed worker JWTs, role/permission policy tests, and enabled tenant filters or explicit tenant predicates.
Session/Token/Cookie Security: 3/10, not production-ready. Strengths: refresh token cookie is HttpOnly, Secure, SameSite=Strict, path-scoped in AuthController.java (line 58). Critical: no refresh flow, no logout cookie deletion, no refresh rotation/reuse detection. High: no issuer/audience validation, no key rotation, access tokens remain valid after revocation. Remediate with opaque refresh rotation, token-family reuse detection, issuer/audience validators, kid rotation, CSRF if cookie-based refresh is used.
Password/Credential Security: 4/10, not production-ready. Strengths: Argon2 encoder, hashed refresh/recovery tokens, constant-time token comparison. Critical: password/reset tokens can leak via logs/URLs; reset consume is non-atomic. High: inconsistent password policy: registration min 12 in RegisterRequest.java (line 21), reset min 8 in PasswordResetRequest.java (line 14). Remediate with normalized email, dummy hash for nonexistent users, breached-password checks, atomic Redis Lua consume, and consistent password policy.
MFA/Passkeys/Modern Auth: 0/10, not production-ready. No TOTP, WebAuthn/passkeys, backup codes, MFA recovery, enrollment protection, removal protection, device trust, or step-up auth. Remediate with phishing-resistant WebAuthn first, TOTP as fallback, backup-code hashing, MFA change audit, and step-up requirements for password/session/security changes.
API/Backend Security: 5/10, conditionally production-ready. Strengths: strict Jackson unknown-property/duplicate detection in application.yml (line 59), validation DTOs, structured exception handler, rate limiter, origin firewall. High: log leakage, fail-open Redis abuse controls, no request-size limits, no HSTS/CSP, broad .authenticated(). Remediate with log redaction by object type, endpoint-specific rate limits, request body limits, HSTS, security header policy, and failed-auth metrics.
Frontend Security: 0/10, not production-ready. No frontend exists in the repo. Cannot verify XSS posture, client token storage, route guards, password reset UX, redirect handling, CSRF integration, or dependency bundle risk. Remediate by adding or separately auditing the actual frontend.
Database/Data Model: 3/10, not production-ready. Strengths: UUID PK, unique email, Flyway, ddl-auto=validate. Critical gaps: no session table, audit table, reset-token table, MFA table, terms version table, deletion/anonymization model, timestamps, case-insensitive email unique index. Remediate with durable audit/session/security-event models, lower(email) unique index, token metadata, created_at/updated_at/password_changed_at, and retention/deletion schema.
Infrastructure/Config/Secrets: 3/10, not production-ready. Strengths: env-driven main config, non-root Docker runtime. Critical/high: secret-like values committed, Docker Compose missing WORKER_TOKEN and key mounts, K8s uses latest image and lacks pod security context. Remediate with ExternalSecrets/Vault, digest-pinned images, runAsNonRoot, read-only root filesystem, seccomp, egress NetworkPolicy, real TLS/ingress docs, and production config validation.
Dependency/Supply Chain: 3/10, not production-ready. Strengths: Maven-managed dependency tree resolved. High: no SBOM, no automated CVE gate, no dependency lock/reproducibility policy, GitHub Actions not pinned by SHA, Docker images not digest-pinned. Current advisories require upgrades: Spring Boot to at least 3.5.14, pgjdbc to at least 42.7.11, Spring Security to fixed line where applicable. Add OWASP Dependency-Check or OSV Scanner, CycloneDX SBOM, Renovate/Dependabot, and release signing.
Observability/Auditability/IR: 4/10, not production-ready. Strengths: success audit aspect in AuditLoggingAspect.java (line 103), Prometheus exposure, rate-limit/firewall counters. Gaps: failed login/reset/admin/security changes not durably logged; no alerting; no immutable audit store; email and IP PII handling weak. Remediate with security-event schema, failed/success event taxonomy, correlation IDs, alert rules, and privacy-safe retention.
Performance/Scalability: 4/10, not production-ready. Strengths: Redis/Caffeine rate limiting, async email intent, open-in-view=false. High: Argon2 semaphore bugs; DB lookup on every JWT request in UserAuthoritiesFilter.java (line 46); Redis HKEYS for session listing/revocation; rate limiter cardinality may grow. Remediate with correct semaphores, cache role snapshots with versioning, bounded session counts, per-endpoint rate limits, and load tests.
Reliability/Production Readiness: 3/10, not production-ready. Critical: tests fail. High: registration pre-check race can turn unique violation into 500; email publish occurs inside user transaction in RegistrationService.java (line 41); no outbox/DLQ/retry policy; Redis outage breaks token storage. Remediate with transactional outbox, retry/DLQ, production-like integration tests, startup config validation, and atomic idempotency.
Testing/Verification: 2/10, not production-ready. Strengths: many intended unit/integration tests exist. Critical: suite currently cannot run; CI Java mismatch; H2 create-drop skips Flyway in application-test.yml (line 20); mocked Redis ignores TTL semantics. Remediate by fixing Mockito agent config or replacing inline mocks, aligning CI to Java 21, adding Testcontainers for Postgres/Redis/Rabbit, and testing expiry/race/negative/security cases.
Developer Experience/Maintainability: 6/10, conditionally production-ready. Strengths: package structure is readable, DTOs are explicit, services/controllers are easy to navigate. Weaknesses: comments repeatedly claim protections that are incomplete; security code has subtle bugs; requirements/docs drift from implementation. Remediate with ADRs, accurate docs, smaller security primitives, and threat-model-driven tests.
Compliance/Privacy/Governance: 2/10, not production-ready. Strengths: terms/privacy booleans are captured. Gaps: no terms version, acceptance timestamp/IP, account deletion, export, retention, lawful basis tracking, audit integrity, or PII minimization. Remediate with LGPD/GDPR data lifecycle, export/delete workflows, retention policies, immutable audit logs, and privacy-safe logging.
Performance Bottlenecks
Argon2 semaphore permit inflation defeats CPU/memory protection under load.
UserAuthoritiesFilter performs a database read per authenticated request.
Password hashing uses blocking servlet threads.
Redis fail-open rate limiting permits cross-node amplification during Redis outage.
HKEYS session operations scale poorly with many sessions.
Rabbit/email delivery lacks outbox/backpressure controls.
No load tests prove login/signup/reset throughput.
Threat Model
Credential stuffing/brute force: partially mitigated by IP rate limit and account lockout, but nonexistent emails avoid lockout and endpoint-specific login limits are too loose.
Account enumeration: registration conflict, login timing, lockout behavior, and reset logging leak signals.
Session theft/token leakage: refresh token is HttpOnly, but no rotation/reuse detection/logout; access tokens valid until expiry.
CSRF: currently mostly bearer-token API, but cookie refresh design would need CSRF if implemented.
XSS: frontend absent; backend returns access token in JSON, so client storage becomes critical.
OAuth/OIDC misuse: OAuth is absent despite requirements.
MFA bypass: MFA absent.
Privilege escalation: worker-token auth and unused role model are major risks.
Tenant breakout: tenant filter exists but is not enforced.
Misconfigured CORS: no CORS policy documented; frontend deployment unknown.
Secret leakage: committed secret-like examples and log redaction gaps.
Dependency compromise: vulnerable pgjdbc/Spring Boot versions and no scanner/SBOM.

Risk Acceptance
Accepting current state means accepting account takeover-adjacent reset races, unverifiable tests, token lifecycle gaps, weak role/tenant enforcement, dependency exposure, and poor forensic readiness. These are not cosmetic risks; they directly affect incident containment, abuse resistance, and regulatory defensibility.
Reference Assessment
This is not close to reference-grade. A reference auth system would have complete lifecycle flows, explicit token-family state, atomic recovery flows, phishing-resistant MFA, durable audit trails, strict authorization, verified tenant isolation, reproducible builds, current dependency scanning, and passing production-like tests. AuthKit has good scaffolding, but too many protections are comments, partial implementations, or unverified assumptions.
Final Verdict
Not approved for production. Final strict score: 3/10. It should only be exposed to untrusted users after the P0 items are fixed and verified with passing production-like tests.
